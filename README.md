# Расписание МГУ в Сарове для СКТ-225 и ВМ-126

GitHub Actions выполняет весь цикл синхронизации. Он загружает PDF с официальной страницы филиала МГУ в Сарове, распознаёт занятия и обновляет отдельный Google Calendar каждой группы.

| Группа | Курс | Почасовой запуск | Архив расписания | Последний отчёт |
| --- | --- | --- | --- | --- |
| СКТ-225 | 2 | [17-я минута](https://github.com/retr0-pm/sarov-schedule-skt225/actions/workflows/fetch.yml) | `sarov-schedule` | [Отчёт СКТ-225](https://github.com/retr0-pm/sarov-schedule-skt225/blob/calendar-sync-reports/latest.json) |
| ВМ-126 | 1 | [27-я минута](https://github.com/retr0-pm/sarov-schedule-skt225/actions/workflows/fetch-vm126.yml) | `sarov-schedule-vm126` | [Отчёт ВМ-126](https://github.com/retr0-pm/sarov-schedule-skt225/blob/vm126-sync-reports/latest.json) |

События в обоих календарях используют часовой пояс `Europe/Moscow`. GitHub Actions рассчитывает время запуска по UTC. Минуты запуска совпадают с московским временем.

## Архитектура

1. Workflow запускает офлайн-тесты.
2. Загрузчик читает `https://sarov.msu.ru/raspisanie`, определяет наиболее новый учебный год и семестр и выбирает раздел соответствующего курса.
3. Принимаются только HTTPS-ссылки вида `sarov.msu.ru/sites/default/files/*.pdf` до начала следующего курса или раздела аспирантуры.
4. Каждый ответ проверяется по HTTP-статусу, конечному URL, типу, размеру (по умолчанию до 50 МиБ) и сигнатуре `%PDF-`. Используются тайм-ауты и до трёх повторов временных HTTP-ошибок.
5. Все PDF сначала собираются во временном каталоге. После успешной загрузки всего комплекта создаётся `manifest.json`, и готовый каталог заменяет предыдущий.
6. `pdfplumber` извлекает слова и векторные границы таблиц со всех страниц. Распознаватель восстанавливает строки пар и колонки групп по фактической геометрии, учитывает объединённые ячейки и не использует координаты, жёстко заданные для одного PDF.
7. Распознаватель применяет правила группы и формирует `schedule.json` и `ambiguities.json`. GitHub Actions проверяет эти файлы и комплект PDF перед синхронизацией.
8. В архив расписания входят `manifest.json`, `schedule.json`, `ambiguities.json` и все найденные PDF соответствующего курса. GitHub хранит архив один день.

## Отличия от референса

Архитектурным образцом послужил проект [`surious-type/sarov-schedule-fetch`](https://github.com/surious-type/sarov-schedule-fetch). В референсном репозитории на момент создания этого проекта не было файла лицензии, поэтому код реализован самостоятельно, без копирования исходников.

В этой реализации дополнительно есть:

- парсер на стандартном `html.parser` без Beautiful Soup;
- повторные попытки для временных сетевых ошибок;
- строгая проверка типа, конечного URL, размера и сигнатуры;
- staging и атомарная замена результата;
- отдельная команда повторной проверки готового артефакта;
- явные `download_status`, `validation_status` и `change_status`;
- независимая схема состояния календарной синхронизации и версия правил;
- геометрическое распознавание таблиц без внешних ИИ-сервисов;
- машиночитаемый `schedule.json` со статусами недель и устойчивыми идентификаторами;
- расширенный набор полностью офлайн-тестов.

PDF перечислены в `.gitignore` и никогда не коммитятся.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt -e .
python -m unittest discover -s tests -v
```

**СКТ-225**

```bash
sarov-schedule-fetch --course 2 --output output-skt225
sarov-schedule-validate --profile skt225 output-skt225
sarov-schedule-recognize --profile skt225 output-skt225
sarov-schedule-validate --profile skt225 --require-schedule output-skt225
```

**ВМ-126**

```bash
sarov-schedule-fetch --course 1 --output output-vm126
sarov-schedule-validate --profile vm126 output-vm126
sarov-schedule-recognize --profile vm126 output-vm126
sarov-schedule-validate --profile vm126 --require-schedule output-vm126
```

Для сравнения PDF передайте `--previous-manifest` с путём к манифесту предыдущей проверенной загрузки того же курса. При загрузке без предыдущего манифеста `change_status` получает значение `unknown`.

## GitHub Actions

Помимо почасового запуска, оба сценария можно вызвать вручную через **Actions → Run workflow**. Изменения исходников, тестов, схемы, зависимостей или соответствующего сценария запускают проверки в PR и при отправке в `main`. Для каждой группы рабочие запуски из `main` выполняются последовательно.

Почасовой режим задают переменные `SKT225_SYNC_MODE` и `VM126_SYNC_MODE`. Значение `apply` включает синхронизацию, а `off` приостанавливает её. При ручном запуске из `main` режим `dry-run` читает календарь и публикует план без записи. Проверки в PR и при обычной отправке изменений в `main` выполняются с выключенным календарём.

## Получение артефакта

Откройте последний успешный запуск нужной группы на ветке `main` и скачайте архив из раздела **Artifacts** по имени из таблицы выше. Для загрузки через GitHub API используйте те же критерии. Команда `sarov-schedule-validate --profile <профиль> --require-schedule <каталог>` проверяет распакованный архив, включая SHA-256 каждого PDF и структуру расписания.

## Формат `manifest.json`

Основные поля совместимы с референсной архитектурой:

```json
{
  "schema_version": 1,
  "fetched_at": "2026-11-21T12:00:00Z",
  "source": "https://sarov.msu.ru/raspisanie",
  "semester": "Осенний семестр 2026/2027 учебного года",
  "course": 2,
  "pdf_count": 18,
  "files": [
    {
      "file": "week-01_…pdf",
      "label": "Неделя 1 (1–5 сентября)",
      "week_number": 1,
      "source_url": "https://sarov.msu.ru/sites/default/files/…pdf",
      "size_bytes": 123456,
      "sha256": "…",
      "content_type": "application/pdf",
      "download_status": "success",
      "validation_status": "verified",
      "change_status": "unknown",
      "previous_sha256": null
    }
  ]
}
```

SHA-256 вычисляется по точным байтам PDF. Поэтому обновление документа по прежнему URL обнаруживается. Сравнение может выполняться по номеру недели, а при его отсутствии — по URL. `changed` и `unchanged` показывают только различие байтов между загрузками; они ничего не говорят об успешности календарной синхронизации.

PDF не хранятся постоянно: официальный сайт остаётся источником, а самодостаточный артефакт служит коротким транспортным окном для автоматизации. Это не создаёт лишний публичный архив университетских документов.

## Геометрическое распознавание

На каждой странице алгоритм находит заголовок нужной группы, границы её колонки, строки пар и время. Для каждой строки определяется ячейка, содержащая центр колонки. Общее занятие из объединённой ячейки включается, если она покрывает колонку этой группы.

Горизонтальные границы определяют, является ли блок единым занятием на несколько последовательных пар или отдельными событиями. Несколько спецсеминаров внутри одной ячейки разделяются по самостоятельным блокам «предмет → преподаватель → аудитория». Если дата, таблица, колонка или предмет не определены достоверно, создаётся диагностика `ambiguous`, а неделя получает `safe_for_deletions: false`.

Правила `skt225-v3` находятся отдельно в `rules.py`. Исключаются семейства названий:

- «Особенности нейронных сетей» и «Особенности практического использования нейронных сетей»;
- «Решение нелинейных дифференциальных уравнений» и «Нелинейные дифференциальные уравнения».

Из спецсеминаров СКТ-225 сохраняется только «Параллельные вычисления и анализ алгоритмов».

Правила `vm126-v1` оставляют из спецсеминаров ВМ-126 только «Вычислительную гидродинамику». Из занятий по английскому языку, который в PDF обозначен как «Иностранный язык», исключаются занятия Забродиной без Мордвиновой. Занятия Мордвиновой сохраняются, включая записи с обеими преподавательницами.

## Формат `schedule.json`

Верхний уровень содержит версии схемы и правил, учебный год, семестр, время формирования, отпечаток манифеста, сводный статус, недели, события, исключения и неоднозначности. Схема в `schema/schedule.schema.json` описывает профиль СКТ-225. При проверке ВМ-126 перед синхронизацией валидатор подставляет значения этого профиля.

Пример события:

```json
{
  "source_id": "skt225-v3-…",
  "series_id": "series-…",
  "group": "СКТ-225",
  "date": "2026-12-25",
  "lesson_number": 3,
  "start": "12:30",
  "end": "14:05",
  "timezone": "Europe/Moscow",
  "subject": "Высокопроизводительные вычисления на кластерах с использованием графических ускорителей",
  "teacher": "И.В. Семенов",
  "room": "аудитория Б106",
  "lesson_type": null,
  "source_pdf": "week-17_…pdf",
  "source_pdf_sha256": "…",
  "week_id": "2026-12-21/2026-12-26",
  "recognition_status": "verified"
}
```

`source_id` не строится только из даты и времени: в него входят учебный год, неделя, нормализованная серия предмета и порядковый номер появления этой серии. `series_id` не содержит дату и помогает найти кандидата на перенос. Если кандидатов несколько, календарная автоматизация обязана считать перенос неоднозначным, а не сопоставлять его автоматически.

Статус `recognition.status = verified` допустим только при отсутствии неоднозначных недель. При любом `ambiguous` поле `safe_for_deletions` ложно. Проверенный `schedule.json` предыдущего запуска можно передать через `--previous-schedule`; он сохраняется только как явно неактуальная справочная версия и не подменяет текущие данные.

## Синхронизация Google Calendar

Каждая группа использует свой календарь и сервисный аккаунт. СКТ-225 подключается через ключ в GitHub Actions Secret `SKT225_GOOGLE_SERVICE_ACCOUNT_JSON`. Для ВМ-126 GitHub Actions получает 15-минутный токен Google через Workload Identity Federation. Выдача ограничена запусками сценария ВМ-126 из `main`. Подробности в инструкциях для [СКТ-225](docs/CALENDAR_DEPLOYMENT.md) и [ВМ-126](docs/VM126_DEPLOYMENT.md).

В режиме `apply` календарь приводится к последней проверенной версии расписания. Если ранее импортированное будущее занятие пропало из проверенной недели, оно удаляется автоматически. При однозначном переносе или замене обновляется существующее событие. Если старые и новые занятия нельзя однозначно сопоставить, синхронизация создаёт новые и удаляет устаревшие. Записи, добавленные вручную, и уже начавшиеся занятия сохраняются. При неполном комплекте PDF или ошибке распознавания запись в календарь приостанавливается.

После записи планировщик повторно сверяет календарь и публикует результат в отчёте группы.
