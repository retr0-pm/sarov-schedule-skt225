# Расписание СКТ-225: транспорт PDF из МГУ в Сарове

Репозиторий каждый час получает с официальной страницы филиала МГУ в Сарове полный набор PDF второго курса актуального семестра, проверяет файлы и публикует краткоживущий GitHub Actions Artifact `sarov-schedule`. Отдельная автоматизация ChatGPT сможет скачать этот артефакт, распознать занятия СКТ-225 и синхронизировать их с Google Календарём.

Этот проект **не подключается к Google Calendar** и не объявляет календарь синхронизированным.

## Архитектура

1. Workflow запускает офлайн-тесты.
2. Загрузчик читает `https://sarov.msu.ru/raspisanie`, определяет наиболее новый учебный год и семестр и входит только в раздел `2 курс`.
3. Принимаются только HTTPS-ссылки вида `sarov.msu.ru/sites/default/files/*.pdf` до начала следующего курса или раздела аспирантуры.
4. Каждый ответ проверяется по HTTP-статусу, конечному URL, типу, размеру (по умолчанию до 50 МиБ) и сигнатуре `%PDF-`. Используются тайм-ауты и до трёх повторов временных HTTP-ошибок.
5. Все PDF сначала собираются во временном staging-каталоге. Только после полного успеха создаётся `manifest.json`, результат повторно проверяется и публикуется. Ошибка не заменяет последний корректный локальный каталог неполным.
6. Artifact содержит `manifest.json` и **все** найденные PDF второго курса, а не только изменившиеся. Срок хранения — 1 день.

## Отличия от референса

Архитектурным образцом послужил проект [`surious-type/sarov-schedule-fetch`](https://github.com/surious-type/sarov-schedule-fetch). В референсном репозитории на момент создания этого проекта не было файла лицензии, поэтому код реализован самостоятельно, без копирования исходников.

В этой реализации дополнительно есть:

- парсер на стандартном `html.parser` без Beautiful Soup;
- повторные попытки для временных сетевых ошибок;
- строгая проверка типа, конечного URL, размера и сигнатуры;
- staging и атомарная замена результата;
- отдельная команда повторной проверки готового артефакта;
- явные `download_status`, `validation_status` и `change_status`;
- независимая схема состояния календарной синхронизации и версия правил;
- расширенный набор полностью офлайн-тестов.

## Структура

```text
.github/workflows/fetch.yml       почасовая загрузка и публикация артефакта
.automation/skt225-sync-state.json минимальный начальный шаблон состояния потребителя
docs/CHATGPT_AUTOMATION.md         требования к отдельной автоматизации ChatGPT
src/sarov_schedule/fetcher.py      выбор раздела, HTTP-проверки, SHA-256 и staging
src/sarov_schedule/validate.py     проверка готового каталога по манифесту
src/sarov_schedule/sync_state.py   безопасная фиксация наблюдения PDF
tests/                             офлайн-тесты и фикстуры
```

PDF перечислены в `.gitignore` и никогда не коммитятся.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt -e .
python -m unittest discover -s tests -v
sarov-schedule-fetch --output output
sarov-schedule-validate output
```

Для сравнения с предыдущей успешно проверенной загрузкой:

```bash
sarov-schedule-fetch --output output-new --previous-manifest output-old/manifest.json
```

Отсутствие предыдущего манифеста даёт `change_status: "unknown"`; это не ошибка и не утверждение о состоянии календаря.

## GitHub Actions

Workflow `Fetch Sarov schedule` запускается:

- автоматически каждый час на 17-й минуте (`17 * * * *`, время cron — UTC);
- вручную через **Actions → Fetch Sarov schedule → Run workflow**;
- после изменения загрузчика, тестов, зависимостей или самого workflow в `main`.

Одновременные запуски объединены группой concurrency; старый незавершённый запуск отменяется. Лимит job — 10 минут, разрешение `GITHUB_TOKEN` — только `contents: read`. Публикация выполняется лишь после тестов, полной загрузки и повторной валидации.

Срок хранения задаётся одной строкой `ARTIFACT_RETENTION_DAYS: "1"` в workflow.

## Получение артефакта

В интерфейсе GitHub откройте последний успешный запуск workflow. Внизу страницы в разделе **Artifacts** скачайте `sarov-schedule`. Автоматизация может получить тот же артефакт через GitHub API, выбрав последний успешный run ветки `main` и артефакт с точным именем `sarov-schedule`.

Не используйте артефакт от незавершённого или неуспешного запуска. После скачивания обязательно перепроверьте состав и SHA-256 по манифесту.

## Формат `manifest.json`

Основные поля совместимы с референсной архитектурой:

```json
{
  "schema_version": 1,
  "fetched_at": "2026-11-21T12:00:00Z",
  "source": "https://sarov.msu.ru/raspisanie",
  "semester": "Осенний семестр 2026/2027 учебного года",
  "course": 2,
  "pdf_count": 18,
  "files": [
    {
      "file": "week-01_…pdf",
      "label": "Неделя 1 (1–5 сентября)",
      "week_number": 1,
      "source_url": "https://sarov.msu.ru/sites/default/files/…pdf",
      "size_bytes": 123456,
      "sha256": "…",
      "content_type": "application/pdf",
      "download_status": "success",
      "validation_status": "verified",
      "change_status": "unknown",
      "previous_sha256": null
    }
  ]
}
```

SHA-256 вычисляется по точным байтам PDF. Поэтому обновление документа по прежнему URL обнаруживается. Сравнение может выполняться по номеру недели, а при его отсутствии — по URL. `changed` и `unchanged` показывают только различие байтов между загрузками; они ничего не говорят об успешности календарной синхронизации.

PDF не хранятся постоянно: официальный сайт остаётся источником, а самодостаточный артефакт служит коротким транспортным окном для автоматизации. Это не создаёт лишний публичный архив университетских документов.

## Состояние синхронизации

`.automation/skt225-sync-state.json` — безопасный пустой шаблон. В нём нет токенов, идентификаторов календарей и чужих событий. Для каждой недели потребитель хранит отдельно:

- хеш PDF и результат его проверки;
- `rules_version`;
- календарный статус (`pending`, `verified`, `error` или `ambiguous`);
- дату последней успешной проверки и сведения об ошибке.

Изменение PDF или `rules_version` переводит неделю в `pending`. Только автоматизация, которая действительно прочитала и проверила календарь, вправе установить `verified`. Простая успешная загрузка или совпавший SHA-256 этого не делают.

## Подключение автоматизации ChatGPT

Полная спецификация находится в [`docs/CHATGPT_AUTOMATION.md`](docs/CHATGPT_AUTOMATION.md). Ключевые правила: группа СКТ-225, `Europe/Moscow`, все относящиеся к группе занятия кроме «Особенности нейронных сетей» и «Решение нелинейных дифференциальных уравнений», поддержка объединённых ячеек только при явном участии группы, безопасная обработка переносов/отмен и запрет удаления при неоднозначном распознавании.

Автоматизация ChatGPT создаётся отдельно. Этому репозиторию не нужны доступ к Google Calendar, календарные токены или секреты.
