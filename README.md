# Расписание СКТ-225: транспорт PDF из МГУ в Сарове

Репозиторий каждый час получает с официальной страницы филиала МГУ в Сарове полный набор PDF второго курса актуального семестра, проверяет файлы, детерминированно распознаёт занятия СКТ-225 и публикует краткоживущий GitHub Actions Artifact `sarov-schedule`. Отдельная автоматизация ChatGPT использует готовый `schedule.json` для безопасной синхронизации с Google Календарём.

Этот проект **не подключается к Google Calendar** и не объявляет календарь синхронизированным.

## Архитектура

1. Workflow запускает офлайн-тесты.
2. Загрузчик читает `https://sarov.msu.ru/raspisanie`, определяет наиболее новый учебный год и семестр и входит только в раздел `2 курс`.
3. Принимаются только HTTPS-ссылки вида `sarov.msu.ru/sites/default/files/*.pdf` до начала следующего курса или раздела аспирантуры.
4. Каждый ответ проверяется по HTTP-статусу, конечному URL, типу, размеру (по умолчанию до 50 МиБ) и сигнатуре `%PDF-`. Используются тайм-ауты и до трёх повторов временных HTTP-ошибок.
5. Все PDF сначала собираются во временном staging-каталоге. Только после полного успеха создаётся `manifest.json`; ошибка не заменяет последний корректный каталог неполным.
6. `pdfplumber` извлекает слова и векторные границы таблиц со всех страниц. Распознаватель восстанавливает строки пар и колонки групп по фактической геометрии, учитывает объединённые ячейки и не использует координаты, жёстко заданные для одного PDF.
7. Отдельный модуль применяет правила `skt225-v3`, после чего валидируются `schedule.json` и отчёт неоднозначностей.
8. Artifact содержит `manifest.json`, `schedule.json`, `ambiguities.json` и **все** найденные PDF второго курса, а не только изменившиеся. Срок хранения — 1 день.

## Отличия от референса

Архитектурным образцом послужил проект [`surious-type/sarov-schedule-fetch`](https://github.com/surious-type/sarov-schedule-fetch). В референсном репозитории на момент создания этого проекта не было файла лицензии, поэтому код реализован самостоятельно, без копирования исходников.

В этой реализации дополнительно есть:

- парсер на стандартном `html.parser` без Beautiful Soup;
- повторные попытки для временных сетевых ошибок;
- строгая проверка типа, конечного URL, размера и сигнатуры;
- staging и атомарная замена результата;
- отдельная команда повторной проверки готового артефакта;
- явные `download_status`, `validation_status` и `change_status`;
- независимая схема состояния календарной синхронизации и версия правил;
- геометрическое распознавание таблиц без внешних ИИ-сервисов;
- машиночитаемый `schedule.json` со статусами недель и устойчивыми идентификаторами;
- расширенный набор полностью офлайн-тестов.

## Структура

```text
.github/workflows/fetch.yml       почасовая загрузка и публикация артефакта
.automation/skt225-sync-state.json минимальный начальный шаблон состояния потребителя
docs/CHATGPT_AUTOMATION.md         требования к отдельной автоматизации ChatGPT
src/sarov_schedule/fetcher.py      выбор раздела, HTTP-проверки, SHA-256 и staging
src/sarov_schedule/recognizer.py   геометрия таблиц и генерация schedule.json
src/sarov_schedule/rules.py        независимые правила фильтрации skt225-v3
src/sarov_schedule/validate.py     проверка готового каталога по манифесту
src/sarov_schedule/sync_state.py   безопасная фиксация наблюдения PDF
schema/schedule.schema.json        опубликованная JSON Schema
tests/fixtures/geometry/           снимки геометрии реальных проблемных страниц
tests/                             офлайн-тесты загрузчика, геометрии, правил и схемы
```

PDF перечислены в `.gitignore` и никогда не коммитятся.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt -e .
python -m unittest discover -s tests -v
sarov-schedule-fetch --output output
sarov-schedule-validate output
sarov-schedule-recognize output
sarov-schedule-validate --require-schedule output
```

Для сравнения с предыдущей успешно проверенной загрузкой:

```bash
sarov-schedule-fetch --output output-new --previous-manifest output-old/manifest.json
```

Отсутствие предыдущего манифеста даёт `change_status: "unknown"`; это не ошибка и не утверждение о состоянии календаря.

## GitHub Actions

Workflow `Fetch Sarov schedule` запускается:

- автоматически каждый час на 17-й минуте (`17 * * * *`, время cron — UTC);
- вручную через **Actions → Fetch Sarov schedule → Run workflow**;
- после изменения загрузчика, тестов, зависимостей или самого workflow в `main`.

Одновременные запуски объединены группой concurrency; старый незавершённый запуск отменяется. Лимит job — 10 минут, разрешение `GITHUB_TOKEN` — только `contents: read`.

Последовательность workflow: тесты → загрузка PDF → проверка PDF → распознавание → применение `skt225-v3` → проверка структурированных данных → публикация. Наличие неоднозначностей отражается внутри `schedule.json`: такой результат не помечается как полностью проверенный и запрещает опасные удаления календарных событий.

Срок хранения задаётся одной строкой `ARTIFACT_RETENTION_DAYS: "1"` в workflow.

## Получение артефакта

В интерфейсе GitHub откройте последний успешный запуск workflow. Внизу страницы в разделе **Artifacts** скачайте `sarov-schedule`. Автоматизация может получить тот же артефакт через GitHub API, выбрав последний успешный run ветки `main` и артефакт с точным именем `sarov-schedule`. Для обычной работы календарного потребителя достаточно `manifest.json`, `schedule.json` и `ambiguities.json`; PDF сохраняются для аудита и повторной проверки.

Не используйте артефакт от незавершённого или неуспешного запуска. После скачивания обязательно перепроверьте состав и SHA-256 по манифесту.

## Формат `manifest.json`

Основные поля совместимы с референсной архитектурой:

```json
{
  "schema_version": 1,
  "fetched_at": "2026-11-21T12:00:00Z",
  "source": "https://sarov.msu.ru/raspisanie",
  "semester": "Осенний семестр 2026/2027 учебного года",
  "course": 2,
  "pdf_count": 18,
  "files": [
    {
      "file": "week-01_…pdf",
      "label": "Неделя 1 (1–5 сентября)",
      "week_number": 1,
      "source_url": "https://sarov.msu.ru/sites/default/files/…pdf",
      "size_bytes": 123456,
      "sha256": "…",
      "content_type": "application/pdf",
      "download_status": "success",
      "validation_status": "verified",
      "change_status": "unknown",
      "previous_sha256": null
    }
  ]
}
```

SHA-256 вычисляется по точным байтам PDF. Поэтому обновление документа по прежнему URL обнаруживается. Сравнение может выполняться по номеру недели, а при его отсутствии — по URL. `changed` и `unchanged` показывают только различие байтов между загрузками; они ничего не говорят об успешности календарной синхронизации.

PDF не хранятся постоянно: официальный сайт остаётся источником, а самодостаточный артефакт служит коротким транспортным окном для автоматизации. Это не создаёт лишний публичный архив университетских документов.

## Геометрическое распознавание

На каждой странице алгоритм находит заголовок `СКТ-225`, границы его колонки, строки пар и время. Для каждой строки определяется фактическая ячейка, содержащая центр колонки СКТ-225. Отсутствующая внутренняя граница означает объединённую ячейку, поэтому общее занятие включается только тогда, когда объединение действительно покрывает СКТ-225. Текст соседней колонки не выбирается по близости.

Горизонтальные границы определяют, является ли блок единым занятием на несколько последовательных пар или отдельными событиями. Несколько спецсеминаров внутри одной ячейки разделяются по самостоятельным блокам «предмет → преподаватель → аудитория». Если дата, таблица, колонка или предмет не определены достоверно, создаётся диагностика `ambiguous`, а неделя получает `safe_for_deletions: false`.

Правила `skt225-v3` находятся отдельно в `rules.py`. Исключаются семейства названий:

- «Особенности нейронных сетей» и «Особенности практического использования нейронных сетей»;
- «Решение нелинейных дифференциальных уравнений» и «Нелинейные дифференциальные уравнения».

Из спецсеминаров сохраняется только «Параллельные вычисления и анализ алгоритмов». Обычные дисциплины не исключаются по отдельным совпавшим словам.

## Формат `schedule.json`

Верхний уровень содержит версии схемы и правил, учебный год, семестр, время формирования, отпечаток манифеста, сводный статус, недели, события, исключения и неоднозначности. JSON Schema опубликована в `schema/schedule.schema.json`.

Пример события:

```json
{
  "source_id": "skt225-v3-…",
  "series_id": "series-…",
  "group": "СКТ-225",
  "date": "2026-12-25",
  "lesson_number": 3,
  "start": "12:30",
  "end": "14:05",
  "timezone": "Europe/Moscow",
  "subject": "Высокопроизводительные вычисления на кластерах с использованием графических ускорителей",
  "teacher": "И.В. Семенов",
  "room": "аудитория Б106",
  "lesson_type": null,
  "source_pdf": "week-17_…pdf",
  "source_pdf_sha256": "…",
  "week_id": "2026-12-21/2026-12-26",
  "recognition_status": "verified"
}
```

`source_id` не строится только из даты и времени: в него входят учебный год, неделя, нормализованная серия предмета и порядковый номер появления этой серии. `series_id` не содержит дату и помогает найти кандидата на перенос. Если кандидатов несколько, календарная автоматизация обязана считать перенос неоднозначным, а не сопоставлять его автоматически.

Статус `recognition.status = verified` допустим только при отсутствии неоднозначных недель. При любом `ambiguous` поле `safe_for_deletions` ложно. Проверенный `schedule.json` предыдущего запуска можно передать через `--previous-schedule`; он сохраняется только как явно неактуальная справочная версия и не подменяет текущие данные.

## Состояние синхронизации

`.automation/skt225-sync-state.json` — безопасный пустой шаблон с `rules_version: skt225-v3`. В нём нет токенов, идентификаторов календарей и чужих событий. Для каждой недели потребитель хранит отдельно:

- хеш PDF и результат его проверки;
- `rules_version`;
- календарный статус (`pending`, `verified`, `error` или `ambiguous`);
- дату последней успешной проверки и сведения об ошибке.

Изменение PDF или `rules_version` переводит неделю в `pending`. Только автоматизация, которая действительно прочитала и проверила календарь, вправе установить `verified`. Простая успешная загрузка или совпавший SHA-256 этого не делают.

## Подключение автоматизации ChatGPT

Полная спецификация находится в [`docs/CHATGPT_AUTOMATION.md`](docs/CHATGPT_AUTOMATION.md). Регулярная задача ChatGPT больше не должна каждый час интерпретировать PDF: она проверяет отпечаток `schedule.json`, использует готовые события и выполняет календарное сопоставление. PDF остаются источником для аудита. Удаления запрещены для любой недели, которая не имеет статуса `verified` и `safe_for_deletions: true`.

Автоматизация ChatGPT создаётся отдельно. Этому репозиторию не нужны доступ к Google Calendar, календарные токены или секреты.
