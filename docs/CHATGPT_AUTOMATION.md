# Требования к автоматизации ChatGPT для СКТ-225

Этот документ описывает отдельного потребителя GitHub Actions Artifact. Код данного репозитория не обращается к Google Календарю и не подтверждает календарную синхронизацию.

## Источник и область обработки

- Репозиторий: `retr0-pm/sarov-schedule-skt225`.
- Workflow: `Fetch Sarov schedule`.
- Имя артефакта: `sarov-schedule`.
- Группа: **СКТ-225**, второй курс.
- Часовой пояс событий: **`Europe/Moscow`**.
- Обрабатывать все PDF, перечисленные в `manifest.json`; проверять размер и SHA-256 до распознавания.
- Артефакт самодостаточен: в нём находятся манифест и все опубликованные недели актуального семестра.

## Правила отбора занятий

Применяется список исключений, а не разрешённый список. Для СКТ-225 нужно сохранить все явно относящиеся к группе занятия, включая лекции, практики, спецкурсы и другие виды, кроме ровно двух дисциплин:

1. «Особенности нейронных сетей»;
2. «Решение нелинейных дифференциальных уравнений».

Нельзя автоматически добавлять занятие соседней группы только из-за близкого расположения текста. Занятие из объединённой ячейки учитывается, только если область ячейки или подпись явно включает СКТ-225. «Основы теории графов» и любые другие дисциплины не требуют особого разрешения: они проходят по общему правилу, если относятся к СКТ-225 и не входят в два исключения.

## Безопасная синхронизация

1. Скачать последний успешно завершённый артефакт и проверить `manifest.json`, размеры, сигнатуры PDF и SHA-256.
2. Для каждой недели сопоставить `pdf_sha256` и `rules_version` с `.automation/skt225-sync-state.json`.
3. Повторно обработать неделю, если изменился PDF, версия правил или прошлый статус не был `verified`. Не считать совпадение SHA-256 доказательством успешной синхронизации.
4. Распознать все страницы и колонки недели. При неоднозначности пометить неделю ошибкой и не выполнять опасные удаления.
5. Работать только с будущими/разрешёнными временными диапазонами согласно настройке автоматизации. Время интерпретировать в `Europe/Moscow`.
6. Использовать стабильный системный идентификатор события (например, в расширенном свойстве Google Calendar), включающий источник, группу, дату, время и логическую позицию занятия. Не полагаться только на заголовок.
7. Создавать отсутствующие события, обновлять переносы и изменения, удалять отменённые события только после однозначного полного распознавания соответствующей недели.
8. Не затрагивать события без системного идентификатора этого проекта. Не удалять пользовательские и созданные другими системами события.
9. Перед созданием проверять существующее событие по системному идентификатору, чтобы избежать дубликатов. После изменений повторно прочитать затронутый диапазон и проверить итог.
10. Только после фактической проверки календаря установить `calendar_sync.status = "verified"`, сохранить `last_success_at`, хеш PDF, версию правил, число ожидаемых/найденных событий и выполненные операции.

Если PDF повреждён, структура непонятна, группа не определяется однозначно или проверка календаря не завершилась, синхронизация должна завершиться ошибкой. Соответствующие существующие события при этом нельзя автоматически удалять.

## Минимальное состояние недели

```json
{
  "week_id": "2026-11-23/2026-11-28",
  "pdf_sha256": "…",
  "rules_version": "skt225-v1",
  "pdf": {
    "download_status": "success",
    "validation_status": "verified",
    "changed": true,
    "checked_at": "2026-11-21T12:00:00Z"
  },
  "calendar_sync": {
    "status": "pending",
    "last_success_at": null,
    "last_error": null
  }
}
```

Допустимые календарные статусы: `pending`, `verified`, `error`, `ambiguous`. Загрузчик PDF не вправе самостоятельно устанавливать `verified`.
