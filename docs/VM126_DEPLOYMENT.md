# Расписание ВМ-126

Workflow запускается каждый час на 27-й минуте UTC. Он получает комплект первого курса и извлекает колонку ВМ-126, включая объединённые ячейки, которые её покрывают. Правила `vm126-v1` оставляют спецсеминар «Вычислительная гидродинамика» и исключают занятия по английскому языку с Забродиной, когда в записи отсутствует Мордвинова. Совместные занятия с обеими преподавательницами сохраняются. [Fetch VM-126 schedule](https://github.com/retr0-pm/sarov-schedule-skt225/actions/workflows/fetch-vm126.yml)

Для календаря **«Расписание ВМ-126»** с часовым поясом `Europe/Moscow` используются отдельный ID, сервисный аккаунт и независимый режим работы.

1. Укажите ID этого календаря в переменной `VM126_GOOGLE_CALENDAR_ID` на вкладке [Actions Variables](https://github.com/retr0-pm/sarov-schedule-skt225/settings/variables/actions).
2. Предоставьте сервисному аккаунту доступ только к календарю ВМ-126. Для пробного чтения достаточно просмотра сведений. Для почасового применения выберите **Редактировать (личные мероприятия отображаются как занятое время)**.
3. Настройте [Workload Identity Federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines#github-actions) для GitHub Actions. Ограничьте провайдера числовыми ID владельца и репозитория, веткой `main`, путём `.github/workflows/fetch-vm126.yml` и событиями `schedule` и `workflow_dispatch`. Сопоставьте `google.subject` с `assertion.sub` и `attribute.repository_id` с `assertion.repository_id`. Выдайте этому репозиторию роль `roles/iam.workloadIdentityUser` на сервисном аккаунте ВМ-126. Укажите полное имя провайдера (`projects/.../locations/global/workloadIdentityPools/.../providers/...`) в `VM126_GOOGLE_WIF_PROVIDER`, а адрес сервисного аккаунта в `VM126_GOOGLE_SERVICE_ACCOUNT`. Режим `dry-run` получает 15-минутный токен с доступом на чтение. Режим `apply` получает токен с доступом на запись. При пустом `VM126_GOOGLE_WIF_PROVIDER` workflow поддерживает прежнюю настройку с секретом `VM126_GOOGLE_SERVICE_ACCOUNT_JSON`.
4. Запустите workflow на ветке `main` с `calendar_mode=dry-run`. Сверьте [отчёт ВМ-126](https://github.com/retr0-pm/sarov-schedule-skt225/blob/vm126-sync-reports/latest.json). Для пустого календаря ожидаются только создания будущих занятий.
5. Для включения рабочих запусков задайте `VM126_SYNC_MODE=apply`. Можно сразу выполнить один ручной запуск в режиме `apply` с последующей сверкой отчёта.

Режим `apply` обновляет события по последнему проверенному расписанию. Если ранее импортированное будущее занятие пропало из проверенной недели, оно удаляется автоматически. При однозначной замене в том же временном слоте обновляется существующее событие. При нескольких кандидатах синхронизация создаёт новые занятия и удаляет устаревшие.
